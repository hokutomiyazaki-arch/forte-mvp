## ③ 送信後の検証（過去に対象数のズレの前例あり）

`broadcast_logs` にはバッチIDが無く、1回の送信は**同じ時刻でまとめてINSERT**される
（`src/app/api/admin/broadcast/route.ts`）。直近1時間で切って見る。

```sql
-- 1人1件になっているか（チャネル別）
SELECT channel, status, count(*) AS rows, count(DISTINCT professional_id) AS people
FROM broadcast_logs
WHERE created_at > now() - interval '1 hour'
GROUP BY channel, status
ORDER BY channel, status;

-- 同じ人に2通行っていないか
SELECT professional_id, channel, count(*)
FROM broadcast_logs
WHERE created_at > now() - interval '1 hour'
GROUP BY professional_id, channel
HAVING count(*) > 1;
```

1本目は `rows` と `people` が一致していること。2本目は**0行**であること。
（前回 2026-08-05 の実績: LINE 95・メール167送信・メール26失敗＝計288通・スキップ9人）
