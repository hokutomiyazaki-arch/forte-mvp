## 2. Twilio（SMS）の現在地

**状態: Compliance Profile 記入中。承認待ち。15,000円チャージ済み。**

### 分かったこと（重要）

**日本ではSMS対応のローカル番号が買えない。** Twilio の番号検索で Japan × SMS は 0件。
これは Twilio の不備ではなく国の事情（日本のキャリアはA2P用の番号を卸していない）。

→ **日本宛ての唯一の道は Alphanumeric Sender ID（送信者名）**。
　いま記入中の Compliance Profile がその前提。**米国番号を買う案は取り下げ**
　（+1 のロングコードから日本宛ては、キャリアに強くフィルタされ実用にならない）。

### 承認が出たあとの手順

1. Vercel に `TWILIO_SMS_FROM` = 登録した送信者名（**大文字小文字まで完全一致**）
   併せて `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN`
2. **再デプロイ**（入れただけでは反映されない）
3. `https://realproof.jp/api/pro/sms-test` を開いて `enabled: true` を確認（送信せずに確認できる）
4. PCブラウザでログインし、コンソールで `await fetch('/api/pro/sms-test',{method:'POST'}).then(r=>r.json())`
   → 自分の携帯に1通届く（宛先はプロフィール登録済みの自分の番号に固定。踏み台防止）

詳細: `docs/sms/twilio-setup.md`

### 急がなくてよい理由

§17-25 で「既知の不達アドレスは予約作成の瞬間に印が立つ」ようにしたため、
**SMSが無くてもメール未達は検知できる**。SMSは上乗せであって、穴を塞ぐ緊急手段ではなくなった。

## 5. 今夜の教訓（同じ失敗を繰り返さないために）

1. **正規化したアドレスは「同じ人か」を判定するキーであって、宛先ではない。**
   送信・表示に使う値は必ず本人が入力したものを保存する。（§17-20）
2. **例外を持ち回すときは、その理由がその場所にも当てはまるかを必ず確かめる。**
   「予約金が絡むときは逃げ道を残す」を隣のブロックにコピーして、
   メール未達なのに「メッセージを送る」が出ていた。（§17-22）
3. **告知には、ユーザーの画面に見えていない用語を書かない。**
   仕様書を見て書くと、未公開機能（予約金・紹介リスト）の説明が混ざる。（§17-24）
4. **見た目を揃えるだけでは足りない。置き場所も確認する。**
   バナーの CSS を共通化して満足し、マウント位置が違うことに気づかなかった。（§17-23）
5. **「相手からの通知は毎回来る」を前提にしない。**
   Resend は一度バウンスしたアドレスを抑制し、次からは送信もwebhookもしない。
   外部の通知だけに頼らず、こちらが既に知っている事実を使う。（§17-25）
6. **Clerkのセッショントークンは約60秒。** スマホで放置・画面消灯・アプリ切替で更新が止まり、
   復帰後の最初の1回だけ 401 になる。401は黙って1回だけ再送する。（§17-18）
7. **推測で原因を断定しない。** 今夜「相談メールが届かないのは normalizeEmail のせい」と
   結び付けたが、実データを見たら `+` もドットも無く、**単に打ち間違いアドレス**だった。
   バグ自体は本物だったが、その症状の原因ではなかった。**先にデータを見る。**
